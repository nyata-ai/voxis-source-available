# Security policy

## Reporting a vulnerability

Please report a suspected vulnerability privately to [security@nyata.ai](mailto:security@nyata.ai). Do not open a public issue, discussion, or pull request that describes the problem.

## Supported versions

We accept reports against the latest release and the current `main` branch. Older releases are not supported. Please check that the problem still exists on the latest version before you report it.

## What to include

- The version, release tag, or commit you tested.
- How the installation was set up, if it differs from the [installation guide](infra/oss/README.md).
- Clear steps to reproduce the problem, using synthetic data.
- The impact you observed or expect.
- Any mitigation or fix you suggest.

## What not to include

Do not send real audio, transcripts, personal data, passwords, API keys, tokens, OpenBao unseal material, or the address of a live installation. If a report includes sensitive data by mistake, tell us so that we can limit how it is handled.

## What to expect

This is a best-effort process with no guaranteed response time. We try to acknowledge each report within a few working days. We may ask for more detail or a safe reproduction before we can confirm it.

We follow coordinated disclosure. Please give us a reasonable time to release a fix before you publish details. We will agree a disclosure date with you and, if you wish, credit you in the release notes.

This address is not an emergency service.
